# MClash 1.4.0

MClash 1.4 introduces a unified configuration workspace. Imported profiles
remain available as source snapshots, while MClash owns the strategy used at
runtime.

## Unified configuration

- Imports extract and deduplicate node connection data using stable identities.
- Source-owned proxy groups, rules, DNS, TUN and listener sections are not
  executed; the original source remains available for refresh and audit.
- MClash now manages proxy groups, routing rules, rule sets, DNS policies,
  traffic entrances and reusable Workspaces.
- A deterministic compiler generates a complete Mihomo configuration with
  validation, runtime snapshots and recoverable activation.

## Multiple entrances, one strategy

- HTTP, SOCKS5, App Routing and TUN are represented as entrances that follow
  the active Workspace.
- App Routing is now a capability switch; application and process matchers are
  managed with the same unified Rules model and activity is visible in Traffic.
- Failed activation, unavailable nodes, invalid references and DNS conflicts
  remain explicit and recoverable.

## Rockxy-inspired native workbench

- Adds native macOS Sidebar/List/Inspector workspaces for Sources, Nodes, Proxy
  Groups, Rules, Workspaces and Entrances.
- Supports search, responsive Inspector collapse, editing aliases/group
  membership/rule targets/workspace bindings, and stable keyboard-friendly
  selection behavior.
- Keeps MClash system colors, SF typography, accessibility labels, localized
  UI, dark mode and reduced-motion behavior.

## Upgrade and safety

- Existing profile YAML, App Routing snapshots and automation commands remain
  available through the migration boundary while new configuration state is
  stored separately.
- Backups now include the authoritative MClash Configuration directory and
  continue to restore transactionally without deleting components absent from
  older backups.
