# 开始使用 MClash 1.6

MClash 管理你的节点、节点组和路由规则。Xray 负责建立代理连接。添加来源只导入节点，不会替换你已经设置的分组、规则和 DNS。

## 添加节点并连接

1. 打开“节点来源”。
2. 选择一种添加方式。
   - 复制了节点分享链接，选择“粘贴链接”。可以一次粘贴多条，也可以粘贴编码后的节点列表或 WireGuard 配置。
   - 有订阅地址，选择“添加订阅”。MClash 会下载并检查内容。
   - 有保存的节点文件，选择“导入文件”。支持的内容包括节点链接、文本列表和包含节点的 YAML。
3. 检查预览或导入结果。
4. 打开“状态”，连接代理。

首次添加节点后，默认节点组会包含导入的节点。你不需要先编辑配置文件。

在“接入方式”中选择哪些流量经过 MClash。系统代理适用于遵循 macOS 代理设置的应用。应用分流需要启用网络扩展。浏览器扩展或其他支持代理的工具也可以使用页面提供的本地地址。

## 管理来源和节点组

“节点来源”中的编辑按钮可以修改名称。订阅还可以修改地址和自动更新设置。刷新订阅会更新节点信息，保留 MClash 中的分组选择。

在“节点”中选择分组方式。

| 方式 | 用途 |
| --- | --- |
| 手动选择 | 自己指定当前节点。 |
| 自动测速 | 按检测结果选择节点。测试地址和切换条件可以进一步调整。 |
| 自动切换 | 优先使用排在前面的可用节点，失败后切换。 |
| 负载均衡 | 将新连接分配到可用节点。 |
| 中继 | 按设置的顺序经过多个节点。 |

测速通过表示测试请求成功，不保证每个网站都能访问。某个节点无法使用时，先在“需要处理”中查看原因，再检查来源或选择其他节点。

## 设置规则

在“规则”中选择匹配条件和目标。目标可以是直连、拒绝或某个节点组。

规则集用于管理一组相同用途的规则。可以手动填写，也可以提供在线列表地址。在线列表更新前会经过检查；下载或验证失败时，MClash 保留之前的规则。可以手动点击“更新规则集”，启用的在线规则集也会每六小时检查更新。

在线规则集中的条目只描述匹配条件。它们使用你在 MClash 中选择的目标，不能自行切换节点组或修改 DNS。

## 查看流量

“连接记录”显示观察到的时间、目标和路径。选中记录后，可以打开详情查看来源地址、协议和原始信息。搜索支持目标地址和节点名称。

这里统计的是已收集的连接事件，列表最多保留最近 2000 条。它不表示仍然活跃的连接数，也不代表目标网站已经成功响应。应用级记录和统计需要 MClash 实际观察到对应的应用流量。

如果显示等待记录，先产生一次经过代理的请求。如果显示读取失败，查看“需要处理”中的提示。内核自动恢复后，记录收集也会恢复。

## 无法连接时

- 先检查来源中是否有已识别的节点，以及当前节点组是否有可用成员。
- 证书验证失败时，使用服务商提供的有效证书设置或固定证书信息。导入“跳过证书检查”的旧设置不会绕过新内核的要求。
- 不支持的节点协议需要更换为当前版本支持的节点。修改名称不会改变协议支持情况。
- 修改系统代理或应用分流后，使用 MClash 的断开和退出操作恢复接入设置。
